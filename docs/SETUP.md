# Как запустить проект

Эта инструкция для любого участника команды. Цель: запустить ADOLAT на своём компьютере с нуля.

## Что нужно

- macOS или Linux. На Windows используйте WSL2.
- Docker Desktop (для баз Postgres и MongoDB).
- Python 3.12 (проект требует `>=3.12,<3.13`).
- Node.js. В `frontend/package.json` версия не указана, а в `frontend/Dockerfile` используется Node 24. Ставьте Node 24.
- pnpm отдельно ставить не нужно: он запускается через corepack (`corepack pnpm ...`), версия `pnpm@11.25.0` записана в `package.json`.
- Git и Git LFS (`brew install git-lfs`, затем один раз `git lfs install`): через LFS хранится готовая база законов `legal_data/seed.sql.gz`.
- Место на диске: модели Ollama занимают около 10 ГБ (см. [MODELS.md](MODELS.md)).
- Память: для локальной модели `gemma3:12b` рекомендуется 16 ГБ. Без модели хватит и меньшего.

## Важно: не держите проект в iCloud

На macOS папки «Рабочий стол» и «Документы» могут синхронизироваться с iCloud. iCloud сильно тормозит чтение тысяч файлов виртуального окружения. Тесты и запуск могут зависать.

Лучше клонируйте проект в обычную папку, например `~/dev/LexHack`.

Если проект всё же лежит в такой папке, назовите окружение `.venv.nosync` и сделайте ссылку `.venv`. Так сделано сейчас в `backend/`. Суффикс `.nosync` говорит iCloud не синхронизировать папку:

```bash
python3.12 -m venv backend/.venv.nosync
ln -s .venv.nosync backend/.venv
```

## Установка по шагам

Все команды запускайте из корня проекта.

1. Клонируйте репозиторий и перейдите в него:

```bash
git clone <адрес-репозитория> LexHack
cd LexHack
```

2. Создайте виртуальное окружение `backend/.venv` на Python 3.12 (если проект в iCloud, используйте вариант с `.venv.nosync` из раздела выше):

```bash
python3.12 -m venv backend/.venv
```

3. Поставьте бэкенд и ingestion (конвейер загрузки законов) в это окружение:

```bash
backend/.venv/bin/pip install -e "backend[dev]"
backend/.venv/bin/pip install -e ingestion
```

4. Создайте файл настроек:

```bash
cp .env.example .env
```

Файл `.env` не попадает в git. Для первого запуска ничего в нём менять не нужно. Без модели и без ключа всё работает без AI.

5. Запустите Docker Desktop и дождитесь, пока он поднимется.

## Запуск одной командой

Первый раз загрузите законы в демо-базу:

```bash
make demo-laws
```

Что это делает. Команда поднимает базы, создаёт демо-базу `adolat_demo` и загружает в неё настоящие законы из `legal_data/`. Законы загружаются как черновик: статус редакции `active`, но поле `verified_by` пусто, то есть юрист ещё не подтвердил текст. Для основной базы так нельзя, это разрешено только для базы, имя которой заканчивается на `_demo`. Если Ollama запущена и в ней есть `bge-m3`, команда заодно считает векторы для смыслового поиска. Если нет, законы загружаются без векторов, и поиск остаётся полнотекстовым. Команда безопасна для повторного запуска.

Затем запускайте всё сразу:

```bash
make dev-all
```

Что поднимается:

| Что | Адрес |
|---|---|
| Postgres | `localhost:5433` |
| MongoDB | `localhost:27018` |
| Бэкенд (демо-база) | http://localhost:8002, Swagger на http://localhost:8002/docs |
| Фронтенд | http://localhost:3000 |

Первый запуск фронта ставит зависимости, это занимает пару минут. Остановить бэкенд и фронт: `Ctrl+C`. Базы при этом продолжают работать в Docker.

### Отдельные команды

Только бэкенд (с демо-данными), без фронта:

```bash
make demo
```

Только базы:

```bash
make db-up
```

Остановить базы:

```bash
docker compose stop
```

Удалить демо-базу, чтобы создать заново (базы должны быть запущены):

```bash
make demo-reset
```

## Тесты

Бэкенд (сам поднимет базы):

```bash
make test
```

Ingestion:

```bash
cd ingestion
../backend/.venv/bin/pytest -q
```

## Бэкенд в Docker

Бэкенд можно запустить в контейнере вместе с базами. Порт на хосте задаётся переменной `BACKEND_PORT` (по умолчанию 8000):

```bash
BACKEND_PORT=8001 docker compose up -d db mongo backend
```

Контейнер сам применяет миграции. Если задан путь `SEED_PATH` и таблицы законов пусты, он загружает готовую базу законов (см. [DATA.md](DATA.md)). В `docker-compose.yml` для этого подключена папка `legal_data/`. Если Ollama нужна из контейнера, в `.env` укажите `OLLAMA_URL=http://host.docker.internal:11434`.

## Частые проблемы

- **Порт занят.** Поменяйте порт переменной: `BACKEND_PORT` (для `make dev` и docker, по умолчанию 8001 в Makefile и 8000 в docker), `DEMO_PORT` (бэкенд в `make demo` и `make dev-all`, по умолчанию 8002), `FRONTEND_PORT` (фронт, по умолчанию 3000). Пример: `DEMO_PORT=8010 make dev-all`.
- **Ollama не запущена.** Это не ошибка. Всё работает без AI: наставник показывает найденные статьи, NPC отвечают заготовками. Как включить модели: [MODELS.md](MODELS.md).
- **Компьютер тормозит после ответа модели.** Модель держит память некоторое время. Освободите её: `ollama stop gemma3:12b`.
- **Тесты зависают.** Проверьте, что проект не лежит в папке с iCloud (см. выше).
- **Первый запуск фронта долго стоит.** Он ставит зависимости, подождите пару минут.
- **`make db-up` пишет, что база не стала healthy.** Проверьте, что Docker Desktop запущен, и посмотрите `docker compose logs db`.
