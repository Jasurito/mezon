# Как собираются правовые данные и дела

Тексты законов не пишутся вручную. Их берут с lex.uz, разбирают программой и кладут в базу. Подробная спецификация: [INGESTION.md](INGESTION.md). Здесь только то, что нужно, чтобы воспроизвести работу.

## Откуда законы

Источник: lex.uz, официальный источник опубликования актов Узбекистана.

- Юридическую силу имеет текст на узбекском. Русские тексты lex.uz помечает как неофициальный перевод.
- Условия lex.uz (https://lex.uz/ru/axborot) разрешают личное использование. Для коммерческого использования нужно письменное разрешение центра «Адолат».
- Автоматического скачивания нет (команда `fetch` выключена). Документы скачиваются вручную, по одной странице, с паузой.

### Текущий корпус

Номера страниц lex.uz взяты из `legal_data/sources.yaml`. Адрес страницы: `https://lex.uz/docs/<номер>`.

| Ключ | Документ | Страница ru | Страница uz-Latn |
|---|---|---|---|
| `CONST` | Конституция Республики Узбекистан | 6445147 | -6445145 |
| `CC1` | Гражданский кодекс, часть первая | 111181 | -111189 |
| `CC2` | Гражданский кодекс, часть вторая | 180550 | -180552 |
| `CPC` | Гражданский процессуальный кодекс | 3517334 | -3517337 |
| `CPRL` | Закон «О защите прав потребителей» (221-I) | 14643 | -4704 |

### Имя файла

Файл с исходной страницей кладётся в `legal_data/raw/` и называется так:

```
<document_key>_<язык>_<дата>.html
```

Пример: `CPRL_ru_2026-11-20.html`. Язык: `ru`, `uz-Latn` или `uz-Cyrl`. Дата: ГГГГ-ММ-ДД. Файл не редактируют.

## Как работает конвейер

Простыми словами, что происходит с каждым файлом:

1. **Разбор HTML.** Из страницы убирается всё лишнее, остаётся текст.
2. **Статьи и части.** Текст делится на статьи и их части.
3. **Чанки.** Статьи режутся на небольшие куски для поиска.
4. **Векторы.** Если включён `EMBEDDER`, для кусков считаются векторы (см. [MODELS.md](MODELS.md)).
5. **Загрузка в Postgres.** Документы, редакции, статьи, чанки.
6. **Ссылки (citations).** Стабильные идентификаторы статей из `legal_data/citations.yaml`.
7. **Проверка.** Целостность данных, отчёт в `legal_data/processed/check_report.md`.

Все команды запускаются из корня проекта. Базы должны работать (`make db-up`).

Собрать черновик `sources.yaml` из скачанных страниц (без базы и сети):

```bash
make ingest ARGS="sources-draft"
```

Если `sources.yaml` уже есть, команда остановится с ошибкой и ничего не перезапишет. Флаг `--force` перезапишет файл, сохранив заполненные поля.

Прогнать весь конвейер:

```bash
make ingest ARGS="run"
```

Только один документ:

```bash
make ingest ARGS="run --doc CPRL"
```

Только проверки:

```bash
make ingest-check
```

Подтвердить редакцию (после проверки человеком, см. ниже):

```bash
make ingest ARGS='activate --doc CPRL --version 21 --by "AB"'
```

Здесь `--version` это `id` редакции в таблице `document_versions`. Идентификаторы выводятся в `check_report.md`, например `version id=21`. `--by` это инициалы проверившего.

Собрать готовый seed (нужен запущенный контейнер `db`):

```bash
make seed-dump
```

Загрузить законы черновиком в демо-базу (то, что вы запускали при установке):

```bash
make demo-laws
```

Отладка отдельных шагов без базы:

```bash
make ingest ARGS="parse --doc CPRL"
make ingest ARGS="segment --doc CPRL"
make ingest ARGS="chunk --doc CPRL"
```

## Что проверяет человек и почему

Программа не знает, какая редакция закона действует. Это определяет человек по lex.uz. В `sources.yaml` для каждой редакции заполняются поля:

- **`effective_from`**: дата вступления редакции в силу. Смотрите на lex.uz в списке редакций. Дата скачивания и дата на странице не подходят.
- **`is_official_text`**: официальный ли это текст (узбекский) или неофициальный перевод.
- **`verified_by`**: инициалы человека, который всё проверил.

Пока `verified_by` пуст, редакция получает статус `pending_review` и в основной базе не используется. Исключение: черновик можно загрузить только в демо-базу `adolat_demo` (`make demo-laws`, флаг `--draft-activate`). Для обычных баз этот флаг не работает.

Seed не собирается, пока в базе, с которой снимается дамп, есть активные редакции без `verified_by` (`make seed-dump` остановится с ошибкой). Демо-база с черновиками для seed не годится.

Сейчас все редакции корпуса загружены черновиком: `verified_by` пуст у всех. `check_report.md` честно показывает это ошибками.

## citations.yaml

Файл `legal_data/citations.yaml` связывает сценарии с законами. Каждая запись это стабильный идентификатор статьи вида `CPRL.art.14` (документ, слово `art`, номер статьи).

Как добавить ссылку. Скопируйте образец из `legal_data/citations.example.yaml` и заполните поля:

```yaml
- citation_id: CPRL.art.14
  document_key: CPRL
  article_number: "14"        # строкой, как в базе
  part: null                  # номер части статьи или null
  topic: "о чём статья, одной фразой"
  verified_by: "AB"           # инициалы проверившего; null, пока не проверено
```

Номер статьи берите из разобранного текста (`legal_data/processed/*.articles.jsonl`), не выдумывайте. После правки запустите `make ingest ARGS="run"`.

## Seed

Seed (`legal_data/seed.sql.gz`) это готовая база законов вместе с векторами. Новому участнику не нужно заново разбирать все документы.

- Собирается командой `make seed-dump` после проверки человеком.
- Содержит только данные правовых таблиц (без схемы).
- Хранится в git через Git LFS (`.gitattributes`): в истории лежит только ссылка, сам файл — на GitHub LFS. `git pull` скачивает его автоматически, если установлен git-lfs.
- Бэкенд в docker загружает seed при старте, если таблицы законов пусты (путь задаётся `SEED_PATH`, в `docker-compose.yml` это `/seed/seed.sql.gz`).

Для локальной работы seed не нужен: хватит `make demo-laws`.

## Что в git, а что нет

В git:

- `legal_data/raw/`: исходные HTML, источник истины.
- `legal_data/sources.yaml` и `legal_data/citations.yaml`.
- `legal_data/processed/check_report.md` (и `article_counts.json`).

Не в git (см. `.gitignore`):

- `legal_data/processed/*.jsonl`: пересобирается за минуту.
- `legal_data/processed/embeddings_cache/`: кэш векторов.
- `legal_data/seed.sql.gz`: хранится через Git LFS.

## Как добавить новый закон или новую редакцию

1. Откройте документ на lex.uz нужного языка и нужной редакции. Сохраните страницу целиком («Сохранить как», только HTML). Не редактируйте файл.
2. Назовите файл `<ключ>_<язык>_<дата>.html` и положите в `legal_data/raw/`.
3. Обновите `sources.yaml`: для нового документа вызовите `make ingest ARGS="sources-draft --force"` или допишите записи по образцу `legal_data/sources.example.yaml` вручную. Укажите `source_url`, `effective_from` по lex.uz и `retrieved_at`.
4. Прогоните `make ingest ARGS="run --doc <ключ>"`. Новая редакция попадёт в базу как `pending_review`.
5. Человек сверяет статьи по `legal_data/processed/check_report.md`, заполняет `is_official_text` и `verified_by` в `sources.yaml` и подтверждает редакцию командой `activate` (см. выше).
6. Если на документ ссылаются сценарии, добавьте записи в `citations.yaml`. Затем `make ingest-check` и `make seed-dump`.

## Дела (сценарии)

Дела лежат в `scenarios/`. Одно дело это папка, например `scenarios/consumer_moisture_001/`. В ней четыре файла:

- `scenario.json`: ход дела, роли, ссылки на статьи (список `citations`);
- `quiz.json`: вопросы;
- `texts.ru.json` и `texts.uz-Latn.json`: тексты. Оба языка обязательны.

Схема дела: `backend/app/schemas/scenario.schema.json` (для вопросов: `quiz.schema.json`). Образец для копирования: `backend/tests/fixtures/scenarios/test_consumer/`.

При старте сервер проверяет два условия: файлы подходят под схему, и каждая статья из `citations` дела есть в базе. Если статьи нет, сервер не запустится. Проверку отключает `STRICT_CITATIONS=false`, но делать это стоит только для отладки.

Как добавить дело:

1. Скопируйте папку `backend/tests/fixtures/scenarios/test_consumer/` в `scenarios/<новый_id>/`.
2. Измените `scenario_id` и содержимое файлов. Тексты на `ru` и `uz-Latn`.
3. Убедитесь, что все `citations` дела есть в `legal_data/citations.yaml`, и загрузите законы (`make demo-laws`).
4. Запустите `make demo` и проверьте, что сервер стартует без ошибок. Подробности о формате: [BACKEND.md](BACKEND.md).
